## 1. 系统/方法概述
本仓库是一个单文件 Python + tkinter 桌面程序（`差旅记录.pyw`），**没有使用任何外部配置框架或配置文件格式**。所有运行期“可配置项”均以模块级常量、字符串字面量以及基于 `sys.executable` / `__file__` 推导出的相对路径的形式硬编码在代码中。唯一的独立配置文件是根目录下的 `reasonix.toml`，但它仅用于 Reasonix 工具权限声明（`[permissions] allow = [...]`），与应用运行时配置无关。

## 2. 关键位置
- `差旅记录.pyw`：唯一包含配置相关逻辑的文件，集中在文件顶部约 35 行。
- `data/`：运行时数据目录（SQLite 数据库、截图）。由代码自动创建。
- `导出文件/`：Excel 导出输出目录。由代码自动创建。
- `reasonix.toml`：Reasonix 工具的权限白名单，非应用配置。

## 3. 架构与约定
### 3.1 路径解析策略（核心）
应用通过 `sys.frozen` 判断是否被打包为 exe，从而决定基准目录：
```python
if getattr(sys, 'frozen', False):
    BASE_DIR = os.path.dirname(os.path.abspath(sys.executable))
else:
    BASE_DIR = os.path.dirname(os.path.abspath(__file__))
```
随后派生：
- `DATA_DIR = BASE_DIR/data`
- `SCREENSHOTS_DIR = DATA_DIR/screenshots`
- `EXPORT_DIR = BASE_DIR/导出文件`
- `DB_PATH = DATA_DIR/差旅记录.db`

这意味着：**数据库和截图必须位于 exe/py 所在目录的 `data/` 子目录下**；导出文件默认写入同级 `导出文件/` 目录。该约定由 `db_init()` 中的 `os.makedirs(..., exist_ok=True)` 保证目录存在，并由 `save_screenshot()` 以相对于 `BASE_DIR` 的正斜杠路径持久化到数据库。

### 3.2 枚举型配置（字典/列表常量）
以下“配置”以 Python 常量形式集中定义在模块顶层：
- `TRANSPORT_OPTIONS = ['公共交通','打车','公共交通+打车','甲方提供','我方租车']`（两处重复定义，一处约第 31 行，另一处约第 303 行）
- `MEAL_TYPES = ['早餐','午餐','晚餐','下午茶','夜宵','其他']`
- `WEEKDAY_NAMES = ['星期一', ..., '星期日']`
- `IMG_EXTS = ('.png','.jpg','.jpeg','.bmp','.gif','.webp')`：允许的图片扩展名白名单，用于截图保存时校验/补全。
- `FONT = ('Microsoft YaHei UI', 10)`、`FONT_BOLD = ('Microsoft YaHei UI', 10, 'bold')`：界面字体。

这些常量直接作为 `ttk.Combobox(values=...)` 的选项来源，构成用户输入的唯一合法值域。

### 3.3 数据库 schema 即“结构配置”
表结构（`trips`、`lodging`、`meals`、`transports`）在 `db_init()` 中以 `CREATE TABLE IF NOT EXISTS` SQL 字符串内联定义，并附带一个幂等的 `migrate_legacy_trips()` 迁移函数，把旧 `trips` 表中的餐饮/交通字段迁移到新表。schema 变更只能通过修改源码实现，无版本化迁移脚本。

### 3.4 启动入口与初始化顺序
`main()` 调用顺序固定：`db_init()` → 构造 `MainApp()` → `app.mainloop()`。异常被捕获后弹出 `messagebox.showerror('程序错误', ...)`。

## 4. 约定与约束
- **单一部署单元**：所有数据（`.db`、截图、导出 xlsx）必须与 `差旅记录.exe` 同目录；移动 exe 会连带移动数据目录，否则应用无法找到数据。
- **无环境变量读取**：代码未调用 `os.environ`，不存在通过环境变量覆盖行为的能力。
- **无外部配置文件加载**：除 Reasonix 工具自身的 `reasonix.toml` 外，应用不读取任何 `.toml/.yaml/.env/.ini` 等配置文件。
- **截图路径存储约定**：数据库中存储的是相对于 `BASE_DIR` 的正斜杠路径（如 `data/screenshots/2026-08-17/meal_xxx.png`），由 `rel_to_abs()` 反向解析。
- **图片格式白名单**：上传截图时若扩展名不在 `IMG_EXTS` 中会被强制替换为 `.png`。
- **日期格式约定**：所有日期以 `YYYY-MM-DD` ISO 字符串存储，由 `parse_date()` 校验，非法则拒绝。
- **向后兼容迁移**：`migrate_legacy_trips()` 确保旧版 trips 表中的餐饮/交通数据能一次性迁移至新表，且幂等执行。

## 5. 结论
该项目采用**“零配置框架、全部硬编码”**的配置方式：路径、枚举、字体、允许的截图格式、数据库 schema 均以内联常量和 SQL 字符串形式固化在 `差旅记录.pyw` 中，通过 `sys.frozen` 检测适配打包/开发两种运行环境。这种设计对小型单机桌面应用足够简洁，但扩展性有限——新增可配置项需要修改源码并重新分发。
